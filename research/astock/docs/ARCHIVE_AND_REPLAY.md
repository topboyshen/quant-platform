# 编译输入留档与离线回放

## 边界

本改动冻结的是**确定性编译的完整输入**，不是让模型重跑后得到同一回答，也不证明研究结论、公告完整性或投资价值。股票池、08:00 截止、发送窗口、独立 notify、XHS DRAFT_ONLY 和 nng8 合同不变。

生产档写入 `work/report-archives/YYYY-MM-DD/`：

- `input.json` / `input.sha256`：原包 UTF-8 文本及字节哈希、解析后原包及规范化哈希、增加研究配置/财务基准后的编译上下文及哈希；stocks/risk/workflow 配置；截止；基础发布审计；候选目录；代码文件指纹、Git revision（如有）、Node/ICU 版本。
- `result/report.md` / `result/result.json`：必须重新编译并经过完整 normalize/来源/时效/确定性门禁后才能生成；保存实际候选选择、选择哈希、输出哈希及财务快照。`compilationInputSha256` 联合绑定前阶段 input 哈希与实际选择，才是最终编译的完整输入身份；基础版和全候选版不能只用前阶段 input 哈希声称输入相同。
- `published.json`：报告与 `reports/daily/YYYY-MM-DD.md` 逐字匹配后写入。仅表示本机正式文件已封存，**不是 Telegram/relay 接收回执**。

日目录和结果目录分别原子落地；已有文件不覆盖。重复运行必须沿用原输入、原截止、原配置、原代码/运行时及已完成的候选选择。异常中断没有发布回执的目录不作为下一份财务基准。`--review-existing` 与 `publish-reviewed.mjs` 也必须通过相同留档/编译约束；后者不能从旧滚动文件倒建凭据。修复代码后不能直接用新代码改写旧档，应先做单独历史验证。

财务基准来自早于本次报告日期的最近一份生产档，并同时检查其输入、结果、回执及磁盘正式稿哈希。旧 `financial-periods.json`（1.0/1.1）不再作为可信比较依据。没有符合条件的档案，必须明示缺基准。比较包括字段值、单位、版本元数据；字段顺序不影响比较；新期、报告期回退、字段/单位/版本变化分别处理。取得利润数据不证明盈利质量或现金流。

这不是防管理员篡改的签名系统，也不替代异机备份。源代码以指纹和 revision 标识，不内嵌完整代码包；回放需要相同源码文件及 Node/ICU。保留 Git bundle/补丁和运行环境，不能只备份 Markdown。

## 时间和查询

- `queryCutoffAt` 是请求截止；`queriedAt` 是实际完成查询时间，不能从请求截止倒填。
- `official_disclosure_query` 只代表查询记录，不是公告事实。查询失败、部分成功、来源/时间无法核验、截止后取得均不是“无公告”。成功的首屏查询仍是有限范围，不声明穷尽窗口。
- 只有披露日期时使用 `disclosureDate`、`timePrecision=date`、真实 `observedAt`；`publishedAt` 必须为空。
- 程序按“实际观察时刻与披露日结束的较早者”计算保守可用边界，但**不把边界显示为发布时间**。同日且截止后才观察到的日期型公告不进入截止前事实；过去日期的事后证据单独保留采集时间。较早观察却标称未来披露日的记录不用于本窗口。
- 股票卡/正文分窗口内条目与近期背景。新鲜/陈旧判断沿用同一证据时间；今天重新采集不使旧公告变新。固定的披露标签不应被误认为另一条同公司媒体事件；自由文本、数字、来源和候选白名单门禁仍然执行。

## 离线命令

在隔离副本中运行；不会调用数据桥、模型、Telegram、XHS 发布或 nng8：

```sh
node scripts/replay-report.mjs create \
  --context /ABS/context.json --date 2026-09-11 \
  --cutoff 2026-09-11T00:00:16.302Z \
  --archive-root /ABS/validation/original-packet --select-all

node scripts/replay-report.mjs verify \
  --archive /ABS/validation/original-packet/2026-09-11
```

创建模式固定为 `historical_validation`，不加载生产财务基准，不允许发布，拒绝生产归档目录（含真实路径别名）。同一目录不能改候选选择；验证基础版和全候选应使用不同目录。没有任何 `normalized ?? compiled` 兜底。

必须在验收说明中区分：

1. **真实冻结包复编译**：保留原包全部字节；用新代码和明确记录的配置重新编译。不是旧版本原正式稿的逐字回放。
2. **事后历史资料重建**：新采集证据使用真实时间，另存原包，不改历史密封件。
3. **模拟边界测试**：用于日期、单位、篡改、重试等边界，不作历史事实证明。

已有历史原包缺失的日期不能凭旧 Markdown 恢复“当时系统所知”。旧混合预览未保存完整 JSON 时，代表性混合路径回归也不能称为该原始输入的忠实回放。
