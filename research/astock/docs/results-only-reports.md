# 面向用户的结果简报

`config/notifications.json` 的 `reportView: "results_only_v1"` 只改变新建日常成功通知的 Markdown 附件展示，不更换来源、股票池、模型或研究规则，也不授予外发权限。

用户收到结论、关键行情、股票池、公告、风险和必要来源；不展开模块评分、生成/核验步骤、研究监控过程及支持/反证列表。未确认判断仍标为推断/待确认，财务口径差异、负面数字、陈旧标记和数据缺口不隐藏。

完整原稿、密封输入、归档及研究审计记录保持不变。XHS 仍使用完整原稿，继续 `DRAFT_ONLY`、禁止自动发布、需要人工批准；摘要 relay 的输入也不改。

## 完整性

- 只有经过原有完整链路批准的原稿可进入通知准备。
- 新结果事件的 `report.reportFile` 保留原稿路径，`sourceSha256/sourceBytes` 绑定原稿。
- `report.presentation` 固定为 `results_only_v1`；`sha256/bytes` 绑定实际结果附件。
- 发出前同时核对原稿、原有密封证明及结果附件，重新生成确定性展示并逐字比较。只改附件再重算摘要也不能通过。
- 不接受未知格式/版本；结果版生成失败时不退回全文，不转成可外发的失败通知。
- 完整原稿仍执行全部数字、来源、时效、候选白名单与逐字编译门禁；展示函数不替代这些验证。

未配置 `reportView` 时保持原全文行为；显式 `full` 同样保持全文。已经存在的事件按照自身原合同处理，不随配置切换改写或重复发送；更正报告保持既有全文合同。任何新展示规则修改都应重新审查其版本兼容性。

外发仍需原来的持久授权和 `ASTOCK_FINAL_DELIVERY=telegram` 两个条件。同日窗口、不可变事件、路径/符号链接限制、单事件发送和不确定回执不自动重试保持不变。本次展示改动不重放或补发历史报告。
