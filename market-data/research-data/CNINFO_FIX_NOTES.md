## 日期语义的来源依据

- [巨潮官方首页](https://www.cninfo.com.cn/new/index) 将此类信息展示为公告的
  “日期”；本次官方 API 返回的午夜时间与附件日期目录一致。
- [深交所创业板业务办理指南（2023 年 8 月版）第 4—5 页](https://docs.static.szse.cn/www/disclosure/notice/W020230804632650900092.pdf)
  区分提交时间与拟披露日期，申请可指定当日、次日或次一交易日。
  这里仅用其证明“提交/观察时间与披露日并非同一语义”，不是宣称此历史版本
  仍是全部现行规则，也不是把规则中的申请时段当作 API 首次公开时刻。

官方响应与上述规则共同支持将字段解释为披露日期标签；实际首次发布时刻仍
未知。`observedAt` 仅表示本次成功收到并解析响应的本地时刻，不冒充首次公开。

## 修改边界

保持原证券池、查询参数、10 条页大小、空日期过滤、完整页检查、HTTPS、证书
验证、无重定向和现有有界重试策略。不引入任何替代来源，不用空列表吞掉失败。

只在以下条件**全部满足**时兼容次日披露日期：

1. 源日期恰为观察日的下一自然日，且源时间为 CST 午夜。
2. 证券代码与查询一致，机构标识与巨潮证券映射一致。
3. 公告 ID 为数字；附件是官方相对路径
   `finalpage/<相同日期>/<相同公告ID>.PDF`（也允许小写 `.pdf`）。

两日或更远未来、跨周末/假期推断的“下一交易日”、非午夜未来时间、缺失或
错误身份/附件证据仍拒绝。该保守边界可能拒绝某些确实合法的长假前公告；
必须另有日期证据后再评估，不能自动扩大窗口或关闭未来日期检查。

每条返回记录新增：

| 字段 | 语义 |
| --- | --- |
| `date` | 原源披露日期，保持不变，不改写成观察日或快照交易日 |
| `dateKind` | 固定 `source_disclosure_date` |
| `observedAt` | 本次响应解析时的 CST 时区时间；同页共用一次真实采集时刻 |
| `nextDayDisclosure` | 是否通过上述有界次日日期兼容 |
| `disclosureEvidence` | 仅次日兼容时保留已匹配的 `orgId`、`announcementId`、`adjunctUrl` |

下游不得依据 `date` 将今天观察到的公告回填到过去交易日，不能把 `observedAt`
当作原始发布时间。现有 `title`、`date` 不变，新增字段为兼容性增补。
附件证据仅表示 API 中身份和路径元数据相互一致，不表示已下载、验签或鉴真 PDF。

`InvalidSchema` 增加有限枚举 `validationReason`，区分对象/总数/页完整性/
行结构/标题时间类型/日期值/超范围/未来日期佐证问题；不把响应内容、地址、
自由文本、异常原文或其他来源字段带入诊断。

## 离线回归覆盖

原 18 项测试保留并适配新增时间元数据，新增 12 项测试覆盖：

- 次日披露日期保留、不回写；`300033` 完整十条与查询范围不变。
- 秒、毫秒及数字字符串一致处理；跨午夜后不再标记为次日。
- 两日及更远未来、周末推断、非午夜未来日期仍拒绝。
- 机构错误、证据字段缺失、附件域名/路径/日期/ID 错误仍拒绝。
- 次日兼容不会绕过不完整页面检查。
- 安全诊断枚举保留，无关敏感字段剔除，恶意类型不会造成诊断函数异常。

本修改不涉及生产数据库、快照锁、业务状态、任务调度、服务重启或任何外发。
部署、使用 VPS 既有依赖的离线测试及最终只读端点验收由主任务统一进行。
